## 2. 주제
기존 협업 도구의 고정된 조직 구조와 파편화된 업무 관리의 한계를 극복하기 위해,  
**모든 조직 주체(Node)와 업무 객체(WorkItem)를 계층형 트리 구조로 일반화**한 협업 프로그램  

**Node** 단위로 github 저장소를 연결하여 **WorkItem** 의 진행사항을 자동 추적하는 등의 기능

**vscode extensions**를 통해서 **Node**의 여러 팀원들과 동시에 코드 공유, 편집 등의 기능

## 3. 필요성 및 기대효과
### 필요성
**협업 도구의 분산 문제**   

일정 관리, 커뮤니케이션, 코드 관리 등등  
툴이 많을수록 맥락이 끊긴다.

- 일정 ↔ 코드 연결 안 됨
- 대화 ↔ 작업 히스토리 분리됨
- “지금 이 작업 상태가 뭐지?” 계속 확인해야 함

=> **협업 비용(커뮤니케이션 비용)이 계속 증가**

---

**개발자 협업의 복잡성 증가**  

프로젝트 규모가 커질수록:

- 여러 명이 동시에 작업
- 의존성 많음
- 일정 변경 잦음

이걸 따로 관리하면  
충돌 (Conflict) 증가, 일정 지연, 책임 불명확

=> **협업 구조 자체를 관리할 시스템이 필요**

--- 

**생산성보다 관리 비용이 커지는 역전 현상**

툴이 많아질수록:

업데이트해야 할 곳 증가,  
중복 입력 발생,  
관리 자체가 일이 됨

=> **일을 하기 위한 도구가 오히려 일을 늘림**

---

### 기대효과

**협업 효율 극대화**  

일정 + 작업 + 커뮤니케이션 통합  
한 곳에서 모든 정보 확인 가능

효과: 불필요한 소통 감소 + 작업 속도 증가

---

**작업 흐름의 가시화**

프로젝트 전체 흐름을 한눈에 파악  
병목 구간 즉시 확인

효과: 문제 대응 속도 향상

---

**개발 생산성 향상**

작업 상태 자동 연동 (ex. 코드 → 일정 반영)  
반복적인 관리 작업 감소

효과: 개발자는 개발에 집중 가능

---

**확장 가능한 협업 구조 구축**

팀 규모 커져도 구조 유지 가능 
체계적인 프로젝트 운영 가능

효과: 스타트업 → 팀 → 조직까지 확장 가능

## 4. 내용 및 기능 요구사항

    - 회원가입

    - 사용자 데이터 동기화

    - 팀 채팅

3. 업무 관리
    - 업무 생성/제거
    - 업무 정보 조회/수정
    - 업무 진행 상태 확인
    - 업무 진행 상태 수정
    - 담당 조직,담당자 지정/변경
    - 상위 업무 설정
    - 시작일 지정/변경
    - 마감일 지정/변경
    - 우선순위 설정
    - 가중치 설정
    - 실시간 상태 동기화
    - 업무 숨김 설정
    - 선행/후속 업무 설정
    - 업무 설명
    - 상태별 그룹화
    - 업무 라이브러리

4. 기타
    - 개인 페이지
    - 사용자 간 메시지 송/수신
    - 실시간 메시지 알림, 수신함
    - 마감 임박 업무 표시
    - 문서 공유
    - 캘린더 기능
    - 휴지통
    - 댓글/메모 작성
    - vscode 익스텐션 연동
    - 팀원 간 실시간 코드 공유 세션
    - 실시간 공유 세션 팀원 초대
    - 실시간 코드 동시 편집

---

### 비기능 요소

1. 사용성
    - 신규 사용자 적응: 신규 사용자가 처음 가입하여 조직을 생성하는 데 걸리는 시간은 ??분 이내
    - 실시간 반응성: VScode 익스텐션 내에서 다른 팀원의 코드 편집 내용을 즉각 반영하여 표시
    - 반응형 디자인: 모바일/태블릿 환경 등 화면 너비가 변경되더라도 가독성 유지

2. 구현
    - 클라이언트  
    Desktop Framework: Electron (OS 알림 및 로컬 파일 시스템/Git 명령어 연동 최적화)  
    React.js, typescript (컴포넌트 기반 UI 구현 및 상태 관리 최적화)  
    - 서버  
    Backend Framework: C++ Drogon Framework (대규모 계층형 노드 연산, 실시간 채팅 	처리 시 고성능 비동기 I/O를 통해 시스템 응답 속도 극대화)  
    Database: PostgreSQL (WITH RECURSIVE 쿼리를 활용한 트리 구조 탐색 및 업무 완료 시 	관련 데이터를 정리하는 Trigger 기능 활용)  
    - 인터페이스  
    Protocol: REST API & WebSocket (실시간 채팅 및 업무 상태 동기화)  
    Integration: Github Webhooks API (Git 활동 추적)  

3. 보안성
    - 사용자의 비밀번호는 서버 저장 시 반드시 암호화 저장한다.
    - 특정 권한이 부여되지 않은 사용자는 조직 설정 변경 등의 기능 이용이 제한된다.

4. 데이터 무결성
    - 동시 편집 중 네트워크 단절이 발생하더라도, 재연결 시 마지막 저장 상태로 자동 복구되어 데이터 유실을 방지한다.

5. 확장성
    - 기능 단위 폴더 구조를 채택하여 새로운 기능 추가 시 기존 코드에 미치는 영향을 최소화한다.
