# 회원가입 이메일 인증 API

회원가입 전에 이메일 소유를 확인하는 API다.
두 엔드포인트 모두 `Authorization` 헤더를 요구하지 않는다.

## 1. 인증번호 요청

| Method | URL |
| :--- | :--- |
| POST | `http://{서버 url}/api/users/email-verification/request` |

### Request

```json
{
  "email": "user@example.com"
}
```

| 파라미터 | 타입 | 필수 여부 | 설명 |
| :--- | :--- | :--- | :--- |
| email | String | 필수 | 인증번호를 받을 이메일(대소문자·앞뒤 공백 정규화) |

### Response

계정 존재 여부, 쿨다운, 시간당 횟수 초과 여부를 응답으로 구분하지 않고 동일한 `200` 을 반환한다.

```json
{
  "status": "success",
  "message": "인증번호를 보냈습니다. 메일이 보이지 않으면 스팸함을 확인해 주세요."
}
```

| 상태 코드 | 의미 |
| :--- | :--- |
| 200 | 요청 접수(실제 발송 여부는 노출하지 않음) |
| 400 | 이메일 누락 또는 형식 오류 |
| 429 | Nginx IP 단위 요청 제한 초과 |
| 500 | 인증번호 생성·DB 처리 실패 |

기본 정책은 인증번호 10분 만료, 이메일당 재전송 60초 쿨다운, 시간당 5회다.
새 인증번호를 발급하면 같은 이메일의 이전 인증번호와 인증 완료 토큰은 폐기된다.

## 2. 인증번호 확인

| Method | URL |
| :--- | :--- |
| POST | `http://{서버 url}/api/users/email-verification/confirm` |

### Request

```json
{
  "email": "user@example.com",
  "code": "123456"
}
```

| 파라미터 | 타입 | 필수 여부 | 설명 |
| :--- | :--- | :--- | :--- |
| email | String | 필수 | 인증번호를 요청한 이메일 |
| code | String | 필수 | 메일로 받은 6자리 숫자 |

### Response

```json
{
  "status": "success",
  "message": "이메일 인증이 완료되었습니다.",
  "verification_token": "64자리_소문자_16진수",
  "expires_in_minutes": 15
}
```

| 파라미터 | 타입 | 설명 |
| :--- | :--- | :--- |
| verification_token | String | 회원가입 API에 전달할 일회용 토큰 |
| expires_in_minutes | Number | 토큰 유효 시간(분) |

인증번호 오류·만료·시도 횟수 초과는 계정이나 코드 상태를 구분하지 않는 일반 오류로 응답한다.

```json
{
  "status": "error",
  "message": "인증번호가 올바르지 않거나 만료되었습니다. 인증번호를 다시 확인해 주세요."
}
```

| 상태 코드 | 의미 |
| :--- | :--- |
| 200 | 인증 완료 및 토큰 발급 |
| 400 | 입력 누락·형식 오류·인증번호 불일치·만료·시도 횟수 초과 |
| 429 | Nginx IP 단위 요청 제한 초과 |
| 500 | 토큰 생성·DB 처리 실패 |

## 저장 방식

- 인증번호는 원문을 저장하지 않고 bcrypt 해시만 저장한다.
- 인증 완료 토큰도 원문 대신 SHA-256 해시만 저장한다.
- 인증번호는 최대 5회까지 확인할 수 있고, 인증 완료 토큰은 15분 후 만료된다.
- 인증 완료 토큰은 회원가입 성공 시 소비되어 재사용할 수 없다.
