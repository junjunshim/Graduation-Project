# [졸업 작품 기획안] 무한 확장형 조직 노드 기반의 협업 및 Git 연동 시스템


## 1. 프로젝트 개요
본 프로젝트는 기존 협업 도구의 고정된 조직 구조와 파편화된 업무 관리의 한계를 극복하기 위해, **모든 조직 주체(Node)와 업무 객체(WorkItem)를 계층형 트리 구조로 일반화**한 차세대 협업 플랫폼입니다. 개발자의 주 작업 환경인 Git 및 VSCode와 실시간으로 동기화되며, 업무 단위의 휘발성 소통 채널을 제공하여 협업 효율을 극대화하는 것을 목표로 합니다.

---

## 2. 핵심 설계 개념 (Core Concepts)

### 2.1. OrganizationNode (공간/주체)
* 회사, 부서, 팀, 개인을 별도의 테이블로 나누지 않고 하나의 `OrganizationNode` 엔티티로 통합 관리합니다.
* **Personal Space First**: 유저는 가입 시 독립적인 `USER` 타입 노드를 배정받으며(parent_node_id = NULL), 이후 필요에 따라 여러 팀 노드에 소속(Join)되는 유연한 구조를 가집니다.

### 2.2. WorkItem (업무/객체)
* 프로젝트, 서브 프로젝트, 할 일(Todo)을 `WorkItem`이라는 단일 모델로 통합합니다.
* 상위 업무와 하위 업무 간의 부모-자식 관계를 통해 업무의 진행 상황이 상향 집계(Roll-up)됩니다.

---

## 3. 데이터베이스 설계 (ERD)



### 🏗 주요 테이블 정의
* **`organization_nodes`**: 트리 구조의 핵심. `path` 컬럼(Materialized Path)을 사용하여 하위 노드 전체를 고성능으로 조회합니다.
* **`users`**: 유저 계정 정보와 개인 고유 노드(`personal_node_id`)를 연결합니다.
* **`role_assignments`**: 유저가 특정 노드에서 가지는 권한(ADMIN, MANAGER, MEMBER)을 관리합니다.
* **`work_items`**: 업무 데이터. `owner_node_id`를 통해 해당 업무가 팀 공용 풀(Pool)인지, 특정 개인 소유인지 결정됩니다.
* **`transient_chats`**: 특정 업무(WorkItem)에 종속된 일회용 채팅 데이터.

## 4. 핵심 및 확장 기능 (Features)

### 4.1. 유연한 업무 할당 (Unassigned Task Pool)
* 본인 외의 팀원이 수행할 할 일(Todo)을 팀 노드(`owner_node_id = TEAM_ID`)에 미리 생성하여 팀 공용 목록에 추가할 수 있습니다.
* 팀원은 공용 목록에서 업무를 확인한 후, 본인의 Todo List로 선택(Pick)하여 가져올 수 있습니다. (선택 시 소유권 변경)

### 4.2. 업무 기반 휘발성 소통 (Transient Communication)
* **공용 메모**: 할 일(Todo) 단위로 팀원들이 실시간으로 수정 가능한 공용 메모를 제공합니다.
* **일회용 채팅방**: 특정 업무에 연결된 실시간 채팅방을 생성하여 집중적인 소통을 지원합니다.
* **자동 정리(Cleanup)**: 해당 할 일이 완료(DONE) 처리되면, 연결된 공용 메모와 채팅방 데이터는 DB에서 자동으로 삭제되어 데이터 무결성과 보안을 유지합니다.

### 4.3. Git 및 VSCode 연동 자동화
* **Git Webhook**: 커밋 메시지에 업무 ID(예: WI-101) 포함 시 백엔드가 이를 감지하여 상태를 자동 업데이트합니다.
* **상태 전파**: 하위 업무 완료 시 상위 프로젝트의 진행률을 PostgreSQL의 재귀 쿼리를 통해 실시간 갱신합니다.
* **VSCode Extension**: IDE 사이드바에서 실시간 업무 확인 및 상태 동기화 기능을 제공합니다.

## 5. 기술 스택 (Tech Stack) 및 선정 사유

### **[Client]**
* **Desktop Framework**: **Electron** (OS 알림 및 로컬 파일 시스템/Git 명령어 연동 최적화)
* **Frontend**: **React.js** (컴포넌트 기반 UI 구현 및 상태 관리 최적화)

### **[Server]**
* **Backend Framework**: **C++ (Drogon Framework)**
    * **선정 사유**: 대규모 계층형 노드 연산 및 실시간 채팅(WebSocket) 처리 시 고성능 비동기 I/O를 통해 시스템 응답 속도를 극대화하기 위함.
* **Database**: **PostgreSQL**
    * **선정 사유**: `WITH RECURSIVE` 쿼리를 활용한 트리 구조 탐색 및 업무 완료 시 관련 데이터를 정리하는 `Trigger` 기능 활용.

### **[Interface]**
* **Protocol**: REST API & WebSocket (실시간 채팅 및 업무 상태 동기화)
* **Integration**: GitHub Webhooks API (Git 활동 추적)

## 6. 기대 효과
1. **아키텍처 우수성**: C++ 기반 고성능 백엔드와 복잡한 트리 구조를 수용하는 데이터 모델을 통해 기술적 차별성 확보.
2. **협업 유연성**: 상향식/하향식 업무 배분을 모두 지원하여 다양한 협업 시나리오 대응 가능.
3. **데이터 최적화**: 업무 단위의 휘발성 소통 채널을 통해 불필요한 데이터 축적 방지 및 협업 집중도 향상.
