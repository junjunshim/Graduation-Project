# 비밀번호 재설정(password reset) 흐름

## 1. 요청 흐름

1. 로그인 화면에서 `비밀번호 찾기`를 누른다.
2. `PasswordResetDialog`가 열리고 로그인 폼에 입력된 이메일을 초기값으로 채운다.
3. 클라이언트가 이메일 형식과 최대 길이(100자)를 검증한다.
4. `requestPasswordResetOnServer`가 `POST /api/users/password-reset/request`를 호출한다.
5. 서버는 이메일을 정규화하고 DB에서 사용자와 쿨다운·시간당 요청 수를 확인한다.
6. 발급 가능한 경우에만 32바이트 난수 토큰을 만들고, SHA-256 해시를 DB에 저장한 뒤 Resend API로 메일을 보낸다.
7. 계정이 없거나 쿨다운 중이어도 클라이언트에는 같은 성공 메시지를 보여 준다.

## 2. 링크 진입 흐름

1. 사용자가 `https://axisflow.team/reset-password/#token=...` 링크를 연다.
2. `app.js`가 fragment에서 토큰을 읽고 주소창에서 fragment를 즉시 제거한다.
3. 토큰이 64자리 16진수가 아니면 사용할 수 없는 링크 화면을 보여 준다.
4. 정상 형식이면 새 비밀번호와 확인 값을 입력받고, 클라이언트가 길이·문자 조합·일치 여부를 검사한다.
5. `POST /api/users/password-reset/confirm`에 `token`과 `new_password`를 보낸다.
6. 서버는 DB 트랜잭션 안에서 토큰 행을 잠그고 만료·사용 여부·사용자 상태를 검증한다.
7. 비밀번호 정책을 다시 검증한 뒤 bcrypt 해시를 갱신하고, refresh token·확장 토큰·남은 재설정 링크를 폐기한다.
8. 성공 화면에서 앱으로 돌아가 새 비밀번호로 로그인하도록 안내한다.

## 3. 실패 처리

| 상황 | 사용자에게 보이는 결과 | 서버 처리 |
| :--- | :--- | :--- |
| 이메일 형식 오류 | 입력 필드 아래 오류 | API 호출하지 않음 |
| 존재하지 않는 계정 | 요청 성공과 동일한 안내 | 메일을 보내지 않고 `requested=false` |
| 쿨다운·시간당 상한 | 요청 성공과 동일한 안내 | 기존 토큰 유지, 새 토큰 발급 안 함 |
| 메일 발송 실패 | 요청 성공과 동일한 안내 | 실패 로그만 남기고 API 응답은 유지 |
| 잘못되거나 만료된 링크 | 재설정 링크 오류 화면 | `P0511` 반환 |
| 비밀번호 정책 위반 | 오류 메시지 표시 | `P0512` 반환, 비밀번호 변경 안 함 |

## 4. 남은 제약

비밀번호 변경 후 refresh token은 삭제되지만, 이미 발급된 access token은 만료 시점까지 유효하다.
모든 기존 access token을 즉시 차단해야 하면 JWT session version/JTI 또는 블랙리스트가 추가로 필요하다.
